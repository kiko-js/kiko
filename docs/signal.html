@kikojs/signal

基于 signal-polyfill 的信号工具集。所有 API 返回标准 Signal.State / Signal.Computed 对象， 与 TC39 Signals 提案兼容，任何消费标准信号的库均可互操作。

适用场景：应用层状态管理、派生计算、副作用协调。
如需 JSX / DOM 渲染，请使用 @kikojs/dom。

安装与导入

bun add @kikojs/signal
import {
  createSignal, isSignal,
  computed, derived,
  effect, onCleanup,
  batch, untrack,
  on,
  createEmitter, createWatcher,
  createStore,
} from "@kikojs/signal"

createSignal

签名说明
createSignal<T>(initial: T): Signal.State<T> 创建可写信号，.get() 读取、.set(v) 写入。 
const count = createSignal(0)
count.set(count.get() + 1)
console.log(count.get()) // 1

isSignal

签名说明
isSignal(value): value is Signal.State | Signal.Computed 类型守卫，判断值是否为 signal。

computed / derived

导出签名说明
computed computed<T>(fn: () => T): Signal.Computed<T> 创建只读派生信号，自动追踪依赖。
derived derived<T>(fn: () => T): Signal.Computed<T> computed 的别名。 
const count = createSignal(1)
const doubled = computed(() => count.get() * 2)
console.log(doubled.get()) // 2
count.set(5)
console.log(doubled.get()) // 10

toSignalValue / watchValue

导出签名说明
toSignalValue toSignalValue<T>(signal): T 读取 signal 当前值。
watchValue watchValue<T>(signal, fn) 监听 signal 变化，自动追踪。

effect

签名说明
effect(fn: () => void | (() => void)): () => void 创建副作用，自动追踪 signal 依赖并重新运行。 返回 dispose() 函数用于手动停止。

核心特性：

  • 批处理：多次 signal 写入合并为一次微任务刷新。
  • 错误隔离：单个 effect 抛出异常不影响其他 effect 或后续重跑。
  • 清理作用域：支持 onCleanup 注册清理回调，重跑前逆序执行。
const count = createSignal(0)
const dispose = effect(() => {
  console.log("count:", count.get())
})
count.set(1) // 微任务后打印 "count: 1"
dispose()     // 停止追踪

onCleanup

签名说明
onCleanup(fn: () => void): void 在当前 effect 作用域注册清理函数。重跑前逆序执行，dispose 时也执行。 
effect(() => {
  const timer = setInterval(() => tick(), 1000)
  onCleanup(() => clearInterval(timer)) // 重跑 / dispose 时清除
})

batch

签名说明
batch<T>(fn: () => T): T 合并 fn 内所有 signal 写入，统一在结束时刷新。 
const a = createSignal(1)
const b = createSignal(2)
effect(() => console.log(a.get(), b.get()))

batch(() => {
  a.set(10)
  b.set(20)
})
// 只打印一次 "10 20"

untrack

签名说明
untrack<T>(fn: () => T): T 在 fn 内读取 signal 不建立订阅关系。 
effect(() => {
  const v = untrack(() => a.get()) // 读取但不订阅 a
  console.log(v, b.get())           // 只在 b 变化时重跑
})

on

签名说明
on(deps, fn, { defer? }): EffectFn 显式依赖 effect 辅助器。仅当 deps 中指定的 signal 变化时才执行 fn；fn 内的其他 signal 读取不会建立依赖。 
const source = createSignal(0)
const other = createSignal(0)

on(source, (v) => {
  console.log(v, untrack(() => other.get())) // other 变化不触发
})

createEmitter

签名说明
createEmitter<Events>(): Emitter<Events> 创建类型化事件发射器。 
type Events = { update: [id: number]; delete: [id: number] }
const emitter = createEmitter<Events>()
emitter.on("update", (id) => console.log("updated", id))
emitter.emit("update", 42)

createStore

创建细粒度响应式对象存储。每个属性都是独立的 Signal.State， 嵌套对象递归包裹为嵌套 store，通过 .get() / .set() 读写。

签名说明
createStore<T>(initial: T): T 返回一个 Proxy，其每个属性都是 StoreSignal（Signal.State 子类）。

核心特性：

  • 属性即 Signal：store.name 返回 Signal.State，可直接传给 JSX 或 computed。
  • 细粒度订阅：只订阅被访问的属性，修改 store.age 不触发 store.name 的 watcher。
  • 嵌套 store：store.user.get() 返回嵌套 store，其属性也是 signal。
  • 自动包裹：.set() 传入普通对象时自动创建嵌套 store。
  • 循环引用检测：检测到循环引用时抛出 TypeError。
const store = createStore({
  name: "Alice",
  user: { age: 30 },
  tags: ["dev"],
})

// 读取 — 每个属性都是 Signal.State
store.name.get()              // "Alice"
store.user.get().age.get()    // 30

// 写入 — 只触发该属性的 watcher
store.name.set("Bob")         // name watcher 触发，age 不受影响
store.user.get().age.set(31)  // user.age watcher 触发

// .set() 自动包裹普通对象为嵌套 store
store.user.set({ name: "Carol", age: 25 })
store.user.get().name.get()   // "Carol" — 不是普通对象，是 Signal.State

// 配合 computed 使用
const greeting = computed(() =>
  `${store.name.get()} is ${store.user.get().age.get()}`
)

// 在 JSX 中直接使用（isSignal → true，自动订阅）
// 
{store.name}
  — 仅当 name 变化时更新

// 循环引用检测
const obj: any = {}
obj.self = obj
createStore(obj)  // TypeError: Circular reference detected in store
